# 單字大富翁（雙人）

## 上線

1. 在**目前新網站使用的 Supabase 專案**，開啟 SQL Editor，貼上 `supabase/migrations/20260927_monopoly_dual.sql` 全部內容並執行。可重複執行；不需要刪資料表、停用 RLS 或更換金鑰。
2. 合併本次 PR，等待 Vercel 完成部署。
3. 首頁「雙人對戰」分類選擇「單字大富翁（雙人）」。若已自訂分類，新入口會加在「單字方塊陣」所在分類；也可在後台分類管理調整。
4. 兩位學生使用各自帳號與裝置，選相同版本、冊數、課程、國家地圖和 10／15／20 回合，再各按「尋找對手」。配對後鎖定設定。

## 規則及紀錄

- 原單人版保留。雙人版沿用地圖、城市介紹、骰子動畫、兩種題型、買地、租金、免租券、機會與命運。
- 雙方輪流行動，彼此各行動一次算一回合。達到回合上限或有玩家現金用盡時結算，以現金決定勝敗，同額為平手。
- 每位玩家看到的我方土地為藍色，對手土地為橘色。
- 「回遊戲選單」會先確認離場，離場者記逃跑，對手獲勝。頁面重整可接回棋盤；90 秒未連線判離場。每日離場上限沿用後台 `pvp_max_escapes`，但只統計此遊戲。
- 後台對戰遊戲開關使用既有 `disabled_games` 陣列，單獨控制 `monopolyDual`；也沿用學生允許遊戲、鎖定課程及開放時段。
- 雙方各有一筆 `game_records`：結算現金、錯誤次數、時間、個人答對／答錯單字、勝敗／平手／逃跑。固定紀錄 UUID 避免重複儲存，任一仍在線的玩家可補存雙方紀錄。
- 學生歷史紀錄、全校／後台英雄榜、後台紀錄報表及對錯分析均有新遊戲選項。英雄榜含勝、敗、逃、平與最高現金；對錯明細取該學生最佳現金紀錄。

## 實作

- 沿用 `game_rooms` 與 Supabase Realtime；以 `monopoly-dual:` 開頭的配對範圍隔離其他遊戲。
- `monopoly_state` 保存完整棋盤。每次更新以 JSON 中的 revision 作條件更新，同一版本只允許一個更新成功；重複按鍵或兩端同時寫入不會重複扣款或跳回合。
- Realtime 廣播通知另一端重新讀取，另以兩秒輪詢補收漏掉的通知。每位玩家十秒更新一次在線時間。只有當前玩家推進骰子與走格，對手端同步觀看。
- 權限沿用現有學生 cookie 及公開房間資料表設計；沒有新增服務端認證或防作弊邊界。
- 本次未改單人版、既有地圖／事件／城市圖片，也未更改既有遊戲的配對流程。
